## 🎯 Goal

CI fails if `frontend/src/api/types.ts` is stale relative to the FastAPI
app's current OpenAPI schema. Prevents a developer from editing back-end
response models and forgetting `make api-types`.

---

## 🔴 Mandatory TDD discipline

Test by intentionally editing the back end without regenerating types,
pushing a branch, observing CI fail, then fixing and observing it pass.

---

## 🪜 Steps

### Step 1 — Red: introduce a stale-types scenario

On a scratch branch, add a new field to a FastAPI response model. Do NOT
run `make api-types`. Commit and push.

**Verify red**: open the PR; CI must fail (added in Step 2).

Commit (later, after fix): `revert: scratch stale-types scenario`

### Step 2 — Green: CI step + freshness check script

`frontend/scripts/check-fresh-types.sh`:
```bash
#!/usr/bin/env bash
set -euo pipefail
cd "$(dirname "$0")/.."

# Regenerate into a temp file, compare to committed.
uv run --project .. python ../scripts/dump_openapi.py
pnpm exec openapi-typescript openapi.json -o /tmp/types.fresh.ts
{
  echo "// AUTO-GENERATED by \`make api-types\`. DO NOT EDIT."
  echo "// Source: usage_dashboard.api:app.openapi()"
  echo ""
  cat /tmp/types.fresh.ts
} > /tmp/types.fresh.ts.tmp
mv /tmp/types.fresh.ts.tmp /tmp/types.fresh.ts

if ! diff -q src/api/types.ts /tmp/types.fresh.ts >/dev/null; then
  echo "ERROR: src/api/types.ts is stale. Run 'make api-types' and commit."
  diff src/api/types.ts /tmp/types.fresh.ts | head -50
  exit 1
fi
echo "types.ts is fresh."
```

Extend the `frontend` job in `.github/workflows/usage-dashboard-ci.yml`:
```yaml
- working-directory: tools/usage-dashboard
  run: uv sync --extra dev
- working-directory: tools/usage-dashboard/frontend
  run: bash scripts/check-fresh-types.sh
```

Re-run CI on the scratch branch — it must now fail with the stale-types error.

Restore the scratch branch: run `make api-types`, commit, push. CI must pass.

Commit: `ci(types): freshness guard against stale generated types`

### Step 3 — Refactor: pre-commit hook (optional but recommended)

Add a `.pre-commit-config.yaml` or a git hook that runs
`check-fresh-types.sh` on every commit touching `usage_dashboard/api/**` or
`frontend/src/api/types.ts`. Optional — CI is the authoritative gate.

Commit: `chore(types): pre-commit freshness hook (optional)`
