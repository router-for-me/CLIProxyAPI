# Fork 上游同步

在自维护 fork 中吸收上游发布的判断流程。机械动作交给脚本，判断留在本文。

## 核心模型

**脚本管机械，skill 管判断。** 两者边界不要混：

| | 归属 | 内容 |
| --- | --- | --- |
| 取 tag、算发布年龄、列提交、跑测试、记档 | 脚本 | 确定性、可重复、无需判断 |
| 值不值得移植、这个行为变更能不能接受、什么时候停下来问人 | 本文 | 需要上下文和立场 |

脚本判定不通过就是非零退出码，不给"建议"。判断做错，脚本拦不住。

## 三道硬门槛

上游版本要同时满足三条，缺一不可：

1. **只跟 release**——不 rebase 上游 `dev`/`main`，那些分支随时会变。
2. **发布满 72 小时**——给上游的回归和仓促补丁浮出水面时间。见习
   `assess-release.sh`，它按 Release 的 `publishedAt` 判定，不是 commit 时间。
3. **回归关卡全绿**——见 `verify-absorb.sh`。

三条是"与"的关系。第一条防的是上游未完成的改动，第二条防的是抢跑，
第三条防的是我们自己没测出来的破坏。

## 先在干净基线上跑一次关卡

**移植任何东西之前，先对当前基线跑一次 `verify-absorb.sh`。**

这不是形式。关卡若在基线上就是红的，你永远分不清后面的失败是你引入的还是继承的。
本仓库第一次运行时就在 `main` 上抓到一个真实 data race（`isClaudeSetupToken`
绕过锁直读 `Auth.Metadata`，上游代码，已随 v1.0.0 发布出去），与本次移植毫无关系。

基线红了就先修基线，别记成"已知豁免"。豁免会让关卡永久失去意义。

## 流程

### 1. 找出候选版本

```bash
ops/upstream-intake/assess-release.sh <new-tag> [<previous-tag>]
```

不带 `previous-tag` 时会和本地命名空间里最近的一个比。首次运行命名空间是空的，
显式传上一版。脚本只写 `refs/upstream/tags/*`，**绝不推送到 origin**。

### 2. 判断移植什么

脚本按 commit message 前缀分类，但**前缀只是线索，不是结论**。逐条看 diff 判断：

| 倾向移植 | 默认跳过 |
| --- | --- |
| 协议/客户端兼容修复 | 上游 CI、构建、依赖升级 |
| 我们已踩到的同类 bug 的修复 | 配置语义变更（会破坏现有用户配置） |
| 安全修复 | 大规模重构（拆分评估，不整段拿） |
| 模型目录、注册表等数据更新 | 纯文档、赞助链接、README |

两条硬规则：

- **逐条 cherry-pick，不整段 merge。** 整段 merge 会把行为变更和无关改动一起带进来，
  之后无法说清"哪条上游提交导致了哪个问题"。
- **上游改了我们已经改过的地方，要读双方 diff 再决定**。这种地方不能用谁的覆盖谁的，
  要按语义合并。

### 3. 记录

在 `ops/upstream-intake/absorbed.md` 追加一行：评估日期、移植的 SHA、跳过的 SHA
及原因、关卡结果。跳过列要诚实——跳过大部分是正常结果，值得写下来。

### 4. 跑关卡

```bash
ops/upstream-intake/verify-absorb.sh
```

非零退出即**不得吸收**。要么在我们这边修，要么放弃该提交并写进 `absorbed.md`。

### 5. 发布

合回 `main`，打我们自己的 `vX.Y.Z`，让 `release.yaml` 出制品。

## "无回归"比你想的更难

关卡全绿只代表**我们测到的范围内**没有回归。移植如果动了请求/响应路径，
还要做差分验证：用同一组固定请求分别打旧版本和新版本，比对响应。

未做差分验证就在记录里写明"未做差分验证"，不要让绿灯被读成"已全面验证"。

## 什么时候停下来问人

- 上游改了我们主线上的核心不变量（如 item ID 命名空间、responses-tools 协议）
- 移植需要改配置语义，会让现有用户配置失效
- 关卡失败但修法涉及架构或公共接口变更
- 同一个上游问题反复回归，说明上游没修根因，继续跟是消耗
- 上游 release 已被我们充分超越，跟进收益低于成本——该说"不再跟"

## 不要做的事

- 不要为了"跟上上游"而 rebase 上游 dev
- 不要把上游 tag 推到 `origin`，会误触发我们自己的 release 流水线
- 不要在关卡失败时打豁免标记让它变绿
- 不要把跳过列留空来显得吸收得更多
