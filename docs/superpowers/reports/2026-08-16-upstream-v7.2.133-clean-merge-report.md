### `.gitignore`

采用双方规则的并集。保留 Fork 的 `.worktrees/`、`.gocache/`、`/.qoder`、`/split_logs`，同时保留上游的 `.gitnexus/`、`docker-compose.override.yml` 和 `.llm-wiki`。

### `docker-compose.yml`

保留 Fork 的主服务、`log-uploader`、`log-qa`、日志目录、TOS 配置、插件数据目录和 QA 配置挂载。插件目录同时兼容 Fork 与上游变量：


`docker compose config --quiet` 验证通过；空测试环境仅提示 TOS 凭证变量未设置。

### `go.mod`

采用上游的 `tiktoken-go/tokenizer v0.8.1`、`golang.org/x/crypto v0.54.0` 和 `golang.org/x/net v0.57.0`，保留 Fork 的 `github.com/volcengine/ve-tos-golang-sdk/v2 v2.9.7`。使用 `go mod tidy` 重新生成 `go.sum`。

### `internal/api/server.go`

采用上游拆分后的 Server 架构，不恢复旧的单文件 Server。Fork 的二开能力迁移并保留在对应职责文件中：

- `server_management_assets.go`：Management HTML 缓存及 Request Log Usage、Log QA 脚本注入。
- `server_management_custom.go`：Fork 管理接口注册。
- `server_middleware.go`：请求日志和 Home 心跳相关中间件。
- `server_routes.go`：上游路由以及 Fork 管理资源路由。
- `server_reload.go`：日志配置热更新。

同时补入 v7.2.133 新增的 `max_completion_tokens` 模型字段及对应测试。

### `internal/logging/request_logger.go`

采用上游拆分后的 RequestLogger 架构，不恢复旧的 2000 行单文件实现。Fork 的日志能力保留在以下职责文件中：

- `request_logger_scope.go`：API Key 名称、no-log Key 和按 Key 日志目录共享状态。
- `request_logger_publish.go`：临时文件写入、同步、无覆盖发布和目录同步。
- `request_logger_writer.go`：非流式请求日志写入。
- `request_logger_streaming.go`：流式请求日志收尾和原子发布。
- `request_logger_format.go`：保持 uploader 依赖的日志区段格式。
- `request_log_policy.go`：配置重载期间的 no-log 策略。

没有引入旧 hardening 分支中尚未完成的鉴权日志决策和请求体捕获实验。
